# 来源对照

建议用 JSON 或表格保存，内部文件与公开输出分开。

每项至少包含：id、信息类别、来源文件、时间段/行号、原文摘录、正文落点、状态、编辑理由。
状态：完整保留 / 部分保留 / 遗漏 / 待核。脱敏为独立标志，不自动等于遗漏。

拆分粒度：一个可独立核验的主张或案例。一个故事里的主要动作、结果与限制可以作为子项，避免将小细节拆成大量单元稀释重要遗漏。主张与支持它的案例分别记录。不同阶段保持相同粒度。

修订时增加 before、after；明确是恢复事实、恢复判断强度、补案例、修正转写还是编辑注释。不把所有修改组都称为新增观点。

汇总示例格式（不预填数字）：
- 核查范围与原始材料限制。
- 已识别信息单元总数及四类状态数量。
- 重要遗漏及原因；核心主张有遗漏时不得宣称完成保真验收。
- 正文字数变化，说明统计是否排除标题、图注和编注。
- 待核事实清单及其发布处理方式。

不需要为了得分计算加权总分。若用户要求百分比，给出明示分母的“完整保留项占比”，同时报告部分保留项，说明人工切分的局限。
